# 签到、背包与游戏圈改版计划

**Goal:** 重做签到和背包的视觉层次，将首页底部齿轮改为当前小游戏的微信游戏圈入口。

**Architecture:** 在 `ui/RewardDialogs.ts` 中绘制两页内容，`StarIsle.ts` 保留签到、保存、联网和页面切换逻辑。独立 `core/WechatGameClub.ts` 管理微信原生按钮的创建、位置、显隐、销毁；由首页和弹窗生命周期控制。原生入口直接使用当前 AppID 的游戏圈，不填写其他小程序或活动地址。

**Tech Stack:** Cocos Creator 3.8.8、TypeScript、现有森林木作贴图、微信 `createGameClubButton`、Node 与导出浏览器回归。

## 设计

在现有森林木作风格内重排信息，避免改成与首页不一致的扁平界面。签到采用今日奖励展示区、六张日历木牌与一张第七天大礼木牌，明确区分已领、今日、待领；保留累计签到、不因间断重置及原有奖励数量。背包采用两列两行木格，放大道具图标，数量作为独立徽章，零库存清晰可见，使用说明置于卡片和底部。大面积改背景或只换颜色都不能解决当前信息层级问题，因此采用结构重排并复用已有素材。

底部入口文字为“游戏圈”，用两只木雕萌宠表现交流入口；系统设置保留在左上角菜单。微信原生透明热区仅覆盖此入口，点击由微信打开本小游戏游戏圈。弹窗、游戏中、后台及场景销毁时不得留下覆盖层；窗口尺寸变化后重新定位。网页预览只提示需在微信中打开，不能伪造成功跳转。

## 执行

- [ ] 实现并先验证原生游戏圈回归：正确当前游戏入口、按屏幕换算、重复显示不重复创建、隐藏销毁、尺寸变化、缺失接口和过期回调。
- [ ] 新增两页绘制模块；签到奖励与库存来自现有存档和奖励表，数量和规则不改。签到按钮在已领取和请求中不重复请求，用户关闭后异步结果不重开页面。
- [ ] 修改首页场景与生成器的第四个快捷入口，接入页面显隐和前后台事件，保留菜单系统设置。
- [ ] 运行源代码检查，导出网页，截图验收两页；浏览器回归覆盖未领/已领、第七天/新一轮、空背包/多位库存、签到防重、游戏圈热区及生命周期。
- [ ] 按审查反馈修复；更新说明，导出微信包并检查启动，在开发者工具验证可用的原生入口行为。

## 验收边界

不改签到奖励数值、消除玩法和道具消耗规则。只在微信平台原生响应确实到达时描述真实游戏圈跳转；模拟 API 测试不能代替该验证。视觉以最终导出截图为准，检查窄屏下文字、按钮及所有七天奖励完整可见。
