# 关卡单一消除规则实施计划

> **For agentic workers:** Use superpowers:subagent-driven-development to implement the independent tasks below, then review specification and code quality. Steps use checkbox syntax.

**Goal:** 后台每关只能选择一种消除组合；现有趣味规则消关卡统一转换为纯 2+2。

**Architecture:** 保留 `rules: number[][]` 的存储和对局协议，但新增、保存、预览、发布关卡只接受一个组合。后台提供 3、4、2+2、其他四选一，“其他”只能输入一个合法组合。历史对局继续解释原始规则，关卡转换通过新发布版本生效。

**Tech Stack:** React 19 / Ant Design、Go / PostgreSQL、Cocos Creator / TypeScript。

## 明确范围

- 选择 3、4、2+2 时替换整个规则数组；其他支持单个 `3+2`、`2+2+2` 等组合，总数 2–7，保留既有数字合法性校验。
- 通过服务端限制多条规则，防止直接调用接口绕过后台单选。
- `fun` 的新默认规则为 `[[2,2]]`。教程由 7 张改为 8 张（4、2、2），第二关仍为 108 张、15 种，每种数量为偶数并能配对。
- 已有关卡转换所有 `mode=fun` 的草稿与当前发布版本。草稿与线上版本分别转换，不发布未发布草稿、不把下架关卡上架、不改通关记录和奖励。
- 方块总数需要为 4 的倍数，每种数量为偶数且单种不超过总数一半。尽量保留布局和种类分布，补齐少量合法格子；必要时调整少量格子或数量，发布版本必须验证能通关。
- 一次性、事务性转换由现有启动初始化流程调用并记录完成标记，可重复启动。保留原版本供进行中的对局和回放使用，旧 `pet-rules-1` 的缺省趣味规则仍按三消或两对解释。
- 其他入口已有多规则配置可读取，但编辑、保存和发布时必须明确选择一个组合；不擅自替运营人员选择其自定义规则。
- 本次完成修改、迁移验证、网页与微信构建；提交和推送按用户后续要求处理。
